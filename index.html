Good software starts with understanding.

Three small moments from software work: a clear request, a question worth asking, and a risk shared early.

USER
PM
DEV
?

01 Clear request

USER “Pelanggan perlu bisa cek status pesanan.”

→▣

DEV “Siap. Status apa saja yang perlu pelanggan lihat?”

USER “Diproses, dikirim, dan selesai.”

DEV “Oke, saya tampilkan status itu di halaman pesanan.”

Jelas kebutuhannya, jelas langkah berikutnya.

Developer menanggapi langsung dan memastikan status apa saja yang perlu dilihat pelanggan. Setelah user menjelaskan, ia merangkum solusi yang disepakati.

02 Clarify first

USER “Bisa tambah diskon pelanggan baru?”

?%

PM “Diskonnya berlaku untuk siapa dan kapan?”

USER “Untuk pembelian pertama.”

PM “Oke. Bisa selesai dalam sehari?”

DEV “Saya cek cakupannya dulu. Hari ini saya kabari estimasi yang lebih pasti.”

Klarifikasi dulu, lalu beri estimasi yang bertanggung jawab.

PM memastikan arti “pelanggan baru” bersama user. Setelah aturannya jelas, Developer tetap tidak menebak durasi: ia mengecek cakupan dan berjanji kembali dengan estimasi pada waktu yang jelas.

03 Raise risk early

DEV · 09.00 “Target 12.00 berisiko mundur; kendalanya ada di sinkronisasi data.”

!12:00

DEV “Bisa rilis bagian inti dulu atau geser target. Saya kabari lagi 10.00.”

PM “Saya cek prioritas dan sampaikan opsinya ke user.”

Risiko disampaikan bersama opsi dan waktu update.

Developer memberi kabar saat masih ada waktu untuk memilih. Ia menjelaskan hambatan, menawarkan opsi, dan menetapkan waktu kabar berikutnya; PM membantu menyepakati prioritas dengan user.
